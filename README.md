# c-foundations

C 语言基础手写实现（不调用标准库的字符串函数）。目的不是"再造一遍轮子"，而是把**指针、内存布局、数组退化、函数参数传递**这四件事，用最短的代码逼到"能预测结果"的程度。

## 实际输出（2026-11-07 20:46 运行验证）

![运行输出](images/test-output-20261107.png)

```
strlen("hello") = 5
strlen("")      = 0
strcpy:hello
ret == buf ? 1
strcpy empty:
strcmp(abc,abd) = -1
strcmp(abc,abc) = 0
strcmp(abc,a)   = 98
```

几点说明：

- `ret == buf ? 1`：`my_strcpy` 返回的就是 `dst` 的首地址，两个指针指向同一个地址。
- `strcpy empty:` 后面是空的：`'\0'` 一落地，`printf("%s")` 立刻停——**这正是"字符串靠结束符划边界"的直接证据**，也是固件里漏写 `'\0'` 会导致溢出的同一条机理。
- `strcmp(abc,a) = 98`：不是 1，而是 `'b' - '\0'` = 98 - 0。**返回值的绝对值没有意义，只保证符号。**

## 三个函数的关键点

**my_strlen**
- 返回类型是 `size_t`（无符号），不是 `int`；`printf` 用 `%zu` 打印。
- 循环条件必须是 `s[n] != '\0'`，不能写成 `n != '\0'`——比较对象搞错就会一直读到越界。

**my_strcpy**
- 必须手动补 `dst[i] = '\0'`；漏掉这一步，`printf("%s")` 会读进缓冲区里的旧数据，甚至越界。
- 返回 `dst` 而不是长度：可以链式调用（`my_strcpy(my_strcpy(a,b),c)`），也是标准库的约定。
- `dst` 的容量由调用者保证——这正是"字符串处理不当导致缓冲区溢出"的来源，也是**固件漏洞最常见的一类成因**。

**my_strcmp**
- `while (*s1 && *s1 == *s2)`：`*s1` 放在前面，既判断"没到结尾"，又能在 `s1` 较短时提前退出，避免读到 `s2` 之外。
- 必须**出了循环再 return**，写在循环体内就只比较第一个字符。
- 返回值的绝对值无意义，只保证"负 / 零 / 正"。

## 踩过的坑（真实记录，都是自己写错的）

1. `my_strcpy` 返回类型写成 `size_t` 却 `return i` → 编译器警告"从整数到指针的隐式转换"。正确是 `return dst`。
2. `my_strcmp` 的 `return` 写进了 `while` 循环体内 → 只比首字符就返回，后面 4 组用例全错。
3. 二维数组写测试用例时，循环边界写死成 `i < 6`，但数组只有 5 行 → 越界读到野值。应该用 `sizeof(A)/sizeof(A[0])`。
4. 把 `my_strcpy` 写进了 `main` 里 → C 不允许函数嵌套定义，报 `E0065 应输入";"`。
5. 调试时把 `main` 整段注释掉 → 报 `LNK2019 无法解析的外部符号 main`。**错误信息指的那一行，往往不是真正出错的地方。**
